# TruthLens — Evaluation Harness

This folder contains the permanent evaluation infrastructure for TruthLens.
Every model version is measured against the same frozen test sets so results
are directly comparable over time.

---

## What each eval set measures

| Set | What it tests |
|-----|---------------|
| `eval_modern` | Clean, unmodified images from current AI generators and real cameras. This is the baseline. |
| `eval_compressed` | The same images after a double-JPEG compression pass (quality 70 → resize ≤ 800 px → quality 60). Simulates what happens to an image forwarded over WhatsApp or Telegram. |
| `eval_screenshots` | The same images rendered as phone screenshots (three device profiles: iPhone 14 Pro Max, Galaxy S24, Pixel 8 Pro). Simulates a user photographing or screen-recording a post. |

The honest expectation is that AUC drops from `eval_modern` to
`eval_compressed` to `eval_screenshots`. That drop is the point — it tells you
how the detector degrades in real-world distribution shift, not how well it
memorised its training set.

```
│   │   ├── ai/    ← place 250+ AI-generated images here

```

## How to populate eval_modern

**AI images (`eval_data/eval_modern/ai/`):**
- At least 250 images spanning multiple generators: Gemini/Imagen, DALL-E 3,
  Midjourney, Stable Diffusion, and any new generators you want to cover.
- Use generators you expect to see in the wild, not just the ones in your
  training set — the eval is supposed to be harder than training.

**Real images (`eval_data/eval_modern/real/`):**
- At least 250 authentic photos.
- Good sources: Wikimedia Commons recent uploads, your own phone photos,
  Unsplash (check license), RAISE-1k dataset.
- Vary the content: portraits, landscapes, objects, text, screenshots of
  legitimate documents.

Supported formats: `.jpg`, `.jpeg`, `.png`, `.webp`, `.bmp`, `.tiff`

The eval images are **not committed to the repo** (they live in `.gitignore`).
The scripts and results JSON are committed.

## How to run

Install dependencies and activate the backend venv first:

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS/Linux
pip install -r requirements.txt
cd ..
```

Then, from the repo root:

```bash
# Step 1: populate eval_modern/ai/ and eval_modern/real/ manually

# Step 2: generate the compressed and screenshot sets
python evaluation/build_eval_compressed.py
python evaluation/build_eval_screenshots.py

# Step 3: run the eval on all three sets
python evaluation/eval_harness.py --eval-set eval_modern --model-version v3
python evaluation/eval_harness.py --eval-set eval_compressed --model-version v3
python evaluation/eval_harness.py --eval-set eval_screenshots --model-version v3

# Or run all three in one command:
python evaluation/eval_harness.py --eval-set all --model-version v3
```

Results are written to `evaluation/results/v3_eval_modern.json` etc.

## How to interpret results

The JSON files in `results/` contain two sections:

### `aggregate`
Top-level metrics:

| Field | Meaning |
|-------|---------|
| `auc` | ROC-AUC. 1.0 = perfect, 0.5 = random. Most important single number. |
| `accuracy` | Fraction correct at threshold p_ai = 0.5. |
| `f1` | F1 score treating AI as the positive class. |
| `ece` | Expected Calibration Error. Lower = better-calibrated confidence. 0.0 = perfect. |
| `false_positive_rate` | Fraction of real images flagged as AI (the user-facing error that matters most). |
| `fpr_at_99pct_real_recall` | FPR when the threshold is set to correctly pass 99% of real images. |
| `confusion_matrix` | TP/FP/FN/TN counts. |
| `signal_contribution_analysis` | Per-signal mean p_ai on AI vs real images. Shows which signals discriminate. |

### `per_image`
One record per image with ground truth label, all signal scores, and the
ensemble verdict. Useful for debugging specific failures.

## How to compare two model versions

Run the eval with a different `--model-version` label:

```bash
python evaluation/eval_harness.py --eval-set eval_modern --model-version v4
```

This writes `results/v4_eval_modern.json`. Then diff the aggregate sections:

```bash
# Quick Python comparison (no extra tools needed):
python - <<'EOF'
import json, pathlib
r = pathlib.Path("evaluation/results")
for ev in ["eval_modern", "eval_compressed", "eval_screenshots"]:
    v3 = json.loads((r / f"v3_{ev}.json").read_text())["aggregate"]
    v4 = json.loads((r / f"v4_{ev}.json").read_text())["aggregate"]
    print(f"\n{ev}")
    for k in ("auc", "accuracy", "f1", "false_positive_rate"):
        delta = (v4[k] or 0) - (v3[k] or 0)
        print(f"  {k}: v3={v3[k]}  v4={v4[k]}  delta={delta:+.4f}")
EOF
```

Do **not** ship a new model version if `false_positive_rate` regresses by more
than 0.02 on any eval set, even if AUC improves. False positives are the
primary user-facing failure mode.

## Adding images to the eval set

1. Add images to `eval_data/eval_modern/ai/` or `eval_data/eval_modern/real/`.
2. Re-run `build_eval_compressed.py` and `build_eval_screenshots.py` to
   regenerate the derived sets (they will overwrite existing files).
3. Re-run the eval harness and commit the updated result JSONs.

Do not add images that appeared in the model's training set. The eval is only
useful if it measures generalisation.

## Honest expectations

- AUC on `eval_modern` for the current model: **to be measured**
- AUC on `eval_compressed`: expect ~0.05–0.15 lower than eval_modern
- AUC on `eval_screenshots`: expect ~0.10–0.20 lower than eval_modern

The training set AUC of ~0.97 is not a meaningful production number. These
three sets give the honest production estimate. We publish whatever they say.
